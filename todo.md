# Power Toys — review findings

Severity: **high** the user sees something wrong or missing, or the item blocks
other work · **medium** it makes changes slow or risky, or costs the user
comfort · **low** polish, tidying, convenience.

Effort: **XS** minutes · **S** under an hour · **M** an hour or a few · **L** a day or more.

Review scope: runtime source, configuration, install/uninstall paths, policy,
udev rules, styles, icons and documentation. Cache, build output, tests and
test-only tooling were excluded as requested.

Review categories: functional correctness; reliability, lifecycle and
concurrency; security and permissions; performance and resource use; UX and
accessibility; internationalization; compatibility and maintainability;
architecture and SOLID; coupling; wiring and integration; state management;
installation and operations; testing and quality assurance; documentation and
assets. Each item names its primary category even where the impact crosses
categories.

| PT-368 | UX and accessibility | blocked | S | low | Blocked: needs a human at a running Cinnamon session, which this environment cannot provide. | PT-379 | Security and permissions | blocked | S | medium | `powertoys-helper:262-290` silently rewrites `charge_control_start_threshold` to `value - 5` (floored at 0) whenever the existing start threshold is at or above the requested end threshold, and restores it only if the transaction fails - so on success a node TLP and vendor utilities commonly own is permanently changed, with nothing in the README, the polkit `<message>` or the applet's change notification saying so. A decision is needed before anything is written: (a) keep the coercion and document it in README's permissions section and in the polkit message the user reads at the password prompt; (b) refuse with `die invalid-value "the start threshold must be lowered first"` and leave the choice to the user; or (c) keep it and report the adjustment back so `Reading.describeChange` can name it in the notification. Each changes what the user is told they agreed to, so it is not ours to pick. |
| PT-421 | Testing and quality assurance | blocked | S | medium | The shell load of PT-420 runs wherever Cinnamon is installed, which is the maintainer's machine and not the CI runner: `ubuntu-latest` has no Cinnamon, so the case skips there and every push is checked by a gate that did not run. Installing `cinnamon-common` and the muffin typelibs on the runner would close that, at the cost of a large apt step in a job whose whole point is that it needs no desktop. Blocked: what a CI minute is worth against a gate that only fires on the maintainer's machine is the owner's call, not ours. |
| PT-422 | Testing and quality assurance | open | XS | low | Two cases still hold the shell sources by regular expression over their text: the `_syncMonitors` body in `tests/cases/loading.js` and the accessible-name call in `tests/cases/accessibility.js` (see PT-312, where a rename broke an unrelated assertion). Both subjects are `PopupMenu` items, which take the process down with them outside a session - there is no Clutter backend and no stage - so neither is convertible where the suite runs, and forcing it would mean moving the case into `tools/shell-load.js`, which is a second runner and only fires where Cinnamon is installed. The counted one is gone: the cancellable tally over four libraries has become a rule that needs no count, and what each module does with the cancellable it owns was already held as behaviour in that module's own case file. |
| PT-423 | Testing and quality assurance | rejected/won't fix | M | medium | `make coverage` measures 6798 lines - 67.7% of the applet - and lists the other 3246 as unmeasured. Now that PT-420 evaluates those files, measuring them looked like the obvious next step, and it is not one. Loading a module runs its body and nothing else: every method of `PowerToysApplet` and of the widget classes would be measured at zero, which is some six hundred functions against a gate that is per function and set at 80%. Reaching them means constructing the applet, and construction is where the absence of a session stops being survivable - a plain `St.Label` builds outside a stage, but `PopupMenu.PopupBaseMenuItem` takes the process down with it. So the figure would either fail permanently or need a second threshold nobody could ever raise, and the honest report is the one the run already prints: what it measured, and what it did not reach. |
| PT-425 | Testing and quality assurance | rejected/won't fix | S | low | `tests/cases/sensors.js` is 1570 lines over four libraries and `tests/cases/ddc.js` 1698 over three, which reads as two files that outgrew their subject. They have not: their subject is how the case is driven, not which module it lands in. `sensors.js` is the sysfs layer against a captured `/sys` - one fixture, one `IO.setRoot`, one plausible machine with cpufreq policies, a battery limit and a platform profile in it - and `tests/cases/cpu.js` and `tests/cases/power-supply.js` say so in their own headers: what is in them is the boundaries a captured tree does not happen to sit on, planted rather than read. Splitting by module would copy the fixture harness into four files and leave each of them holding a third of a machine. |
| PT-435 | Architecture and SOLID | open | M | medium | Grouping header. `applet.js` is 1672 lines and some seventy methods on one class, and it is the file no case can construct: every method moved out of it is a method the suite can exercise and the coverage report can measure, which is why this is worth doing rather than tidy. Three groups of methods on it are not about being an applet at all - they are about talking to the helper, about stepping through profiles, and about what a wheel or a button means - and each already has a library beside it that owns part of the same subject. Unpacked into PT-435a, PT-435b and PT-435c; nothing else in the class is a group rather than a member. |

Moving them into a library beside `lib/helper-messages.js` gives the failure path cases that run anywhere, which today it only has where a session can be opened and a helper broken. |
